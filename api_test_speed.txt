PANDUAN TEST KECEPATAN SELURUH API — REACT + LARAVEL
Tanggal panduan: 2 Oktober 2026

TUJUAN
Ukur seluruh request API yang diperlukan untuk SATU tindakan pengguna sampai
semua respons selesai. Ulangi untuk SEMUA fitur, bukan cuma dashboard.
Panduan ini tidak menyatakan semua fitur sudah di bawah satu detik.

Contoh: klik Login -> autentikasi -> redirect -> data dashboard selesai.
Semua request dalam rantai itu masuk pengukuran "login sampai dashboard".
Jangan mengukur login saja lalu menyimpulkan seluruh alurnya cepat.

Bedakan tiga angka:
1. per request: durasi satu endpoint.
2. total alur API: akhir respons terakhir - mulai request pertama.
3. waktu pengguna: klik -> hasil benar-benar terlihat dan dapat dipakai.

Contoh request paralel 400 ms dan 600 ms: total alur bisa sekitar 600 ms,
bukan otomatis 1.000 ms. Jika berurutan dengan jeda, total dapat lebih besar.
Menjumlahkan kolom Time bukan cara mengukur total alur paralel.
Menjumlahkan semua aktivitas sepanjang sesi satu jam juga bukan SLA satu detik.
"Semua API" berarti seluruh endpoint/alur tercakup dalam daftar pengujian;
target <1.000 ms diuji per alur, bukan seluruh pekerjaan aplikasi selamanya.

2. CARA PALING MUDAH: F12 -> NETWORK

1. Buka F12 -> Network. Pastikan tombol Record menyala.
2. Pilih No throttling untuk baseline internet normal.
3. Aktifkan Preserve log jika alur mungkin berpindah halaman/reload.
4. Centang Disable cache untuk tes tanpa cache BROWSER (DevTools harus terbuka).
   Ini TIDAK menghapus cache OPcache PHP atau cache rute di server.
5. Pilih Fetch/XHR dan isi kotak Filter dengan /api/.
   Untuk gambar bukti tiket, gunakan All + filter /api/ jika Fetch/XHR tidak
   menampilkannya. Request gambar dapat menggunakan tipe Img.
6. Klik Clear sebelum SATU skenario. Tunggu background request sebelumnya selesai.
7. Lakukan satu tindakan: login, buka kiriman, cari resi, simpan kategori, dll.
8. Tunggu data final tampil DAN tidak ada request relevan berstatus Pending.
9. Catat URL tanpa query rahasia, Method, Status, Time, dan jumlah request.
10. Klik request -> Timing untuk melihat pembagian waktunya.
11. Cek Response/Preview: status 200 saja tidak menjamin data benar.
12. Simpan screenshot tabel Network + hasil UI. Sembunyikan data pribadi.

Cara membaca Timing:
- Queueing/Stalled: browser/antrean/koneksi, bukan otomatis query database lambat.
- Waiting for server response (TTFB): menunggu respons pertama; termasuk jaringan
  dan kerja server, bukan waktu database murni.
- Content Download: waktu menerima isi respons.
- Time: durasi request browser, bukan total semua request satu alur.

Waterfall memperlihatkan request berjalan bersama atau berurutan.
Ambil rentang dari awal API pertama sampai akhir API terakhir.
Angka Finish/Load di bawah Network dapat mencakup gambar, script, dan asset lain;
jangan langsung menganggapnya total API saja. Gunakan helper pada bagian 3 untuk
angka API yang presisi. Untuk waktu klik sampai UI siap, gunakan Performance:
rekam sebelum klik, berhenti sesudah UI siap, lihat screenshot/timeline render.

Jangan mengukur hanya /api/health: health tidak membuktikan login/database cepat.
Browser melihat request ke Laravel. Call Laravel -> Supabase/Gemini tidak muncul
sebagai baris browser terpisah; waktunya tetap termasuk dalam respons Laravel.
Gunakan log server pada bagian 7 untuk menelusuri call internal.


3. HITUNG TOTAL OTOMATIS DI CONSOLE, TANPA MENGUBAH PROJECT

Helper berikut hanya membaca timing browser dan menghitung angka.
Tidak mengirim password, tidak membuat request, dan tidak mengubah data aplikasi.
Baca dulu kode sebelum menjalankannya; jangan melewati peringatan keamanan
DevTools untuk kode yang tidak kamu pahami.

BEGIN API SPEED HELPER
(() => {
  let started = null;
  let label = '';
  const round = value => Math.round(value * 10) / 10;
  performance.setResourceTimingBufferSize(5000);

  function report(since, name, includeAction) {
    const calls = performance.getEntriesByType('resource').filter(entry => {
      const url = new URL(entry.name, location.href);
      return url.origin === location.origin && url.pathname.startsWith('/api/')
        && entry.startTime >= since && entry.responseEnd >= entry.startTime;
    });
    if (!calls.length) {
      console.warn('TIDAK ADA API SELESAI: cek Network; ini bukan hasil lulus 0 ms.');
      return { scenario: name, count: 0, apiTotalMs: null };
    }
    const first = Math.min(...calls.map(entry => entry.startTime));
    const last = Math.max(...calls.map(entry => entry.responseEnd));
    const rows = calls.map((entry, index) => ({
      no: index + 1,
      endpoint: new URL(entry.name).pathname,
      startMs: round(entry.startTime - first),
      endMs: round(entry.responseEnd - first),
      durationMs: round(entry.duration),
      ttfbMs: entry.requestStart > 0 && entry.responseStart > 0
        ? round(entry.responseStart - entry.requestStart) : null
    }));
    const result = {
      scenario: name,
      count: calls.length,
      apiTotalMs: round(last - first),
      markerToLastApiMs: includeAction ? round(last - since) : null,
      sumRequestMs: round(calls.reduce((sum, entry) => sum + entry.duration, 0)),
      speedOnlyUnder1s: last - first < 1000,
      correctness: 'BELUM DINILAI: periksa status, response, dan UI di Network'
    };
    console.table(rows);
    console.table([result]);
    return result;
  }

  window.apiSpeed = {
    start(name = 'satu tindakan') {
      started = performance.now();
      label = name;
      console.log('Mulai. Lakukan satu tindakan; stop sesudah seluruh API selesai.');
    },
    stop() {
      if (started === null) throw new Error('Jalankan apiSpeed.start terlebih dahulu.');
      const result = report(started, label, true);
      started = null;
      return result;
    },
    page() { return report(0, 'request sejak navigasi dokumen ini', false); },
    stats(samples) {
      if (!Array.isArray(samples) || !samples.length ||
          samples.some(value => !Number.isFinite(value) || value < 0)) {
        throw new Error('Isi array angka ms valid, bukan null/error/pending.');
      }
      const sorted = [...samples].sort((a, b) => a - b);
      const n = sorted.length;
      const median = n % 2 ? sorted[(n - 1) / 2]
        : (sorted[n / 2 - 1] + sorted[n / 2]) / 2;
      const result = {
        samples: n, minMs: sorted[0], medianMs: round(median),
        p95Ms: sorted[Math.ceil(n * 0.95) - 1], maxMs: sorted[n - 1],
        under1s: sorted.filter(value => value < 1000).length
      };
      console.table([result]);
      return result;
    }
  };
  console.log('Siap: apiSpeed.start, apiSpeed.stop, apiSpeed.page, apiSpeed.stats');
})();
END API SPEED HELPER

Contoh untuk klik submenu tanpa reload:

apiSpeed.start('seller buka arus dana');

Klik submenu Finance -> Arus dana. Tunggu seluruh request selesai dan UI terisi.
Lalu jalankan:

apiSpeed.stop();

Contoh untuk login -> dashboard:
Isi email/password dulu, tanpa submit. Pasang helper, jalankan:

apiSpeed.start('admin login sampai dashboard');

Klik Masuk. Tunggu dashboard terisi. Jalankan apiSpeed.stop().
Jika terjadi full reload, helper hilang; gunakan metode reload di bawah.

Contoh hard reload / buka URL langsung:
1. Buka halaman target dan tekan Ctrl+R dengan Network merekam.
2. Tunggu seluruh data selesai, JANGAN klik fitur lain dulu.
3. Pasang ulang helper di Console, lalu jalankan apiSpeed.page().
   Hasilnya semua API sejak navigasi dokumen saat ini, termasuk bootstrap.
   Jika ada polling/background call, tandai dan pisahkan skenario, jangan abaikan
   diam-diam. page() tidak mengukur waktu klik sebelum navigasi.

Arti hasil:
- apiTotalMs: angka utama total alur API, termasuk jeda antar-request.
- markerToLastApiMs: marker Console -> respons terakhir. Termasuk jeda tangan
  sebelum klik; bukan pengukuran klik tepat maupun waktu render UI siap.
- sumRequestMs: jumlah durasi, hanya diagnostik; bukan target total paralel.
- speedOnlyUnder1s: hanya indikator waktu, BUKAN pernyataan fitur berhasil.

PENTING: Resource Timing hanya berisi request yang telah selesai dan tercatat.
Helper tidak memastikan request pending/gagal/abort semuanya tertangkap, tidak
memvalidasi status HTTP, dan tidak otomatis tahu hasil UI benar atau belum.
Cocokkan count dengan Network; jika berbeda, pending, abort, buffer penuh,
atau ada request lintas origin, hasil belum lengkap. Ulangi skenario.
Helper ini mengukur API same-origin /api/ saja; tile peta dan image eksternal
dicatat terpisah pada bagian peta, jangan mengklaim semuanya ikut dihitung.
Tidak menampilkan query string, body, cookie, atau password.

6. ULANGI DAN NILAI DENGAN BENAR

Catat satu sampel awal (first observed/cold candidate) secara terpisah.
Koneksi/backend cache mungkin sudah hangat, jadi jangan klaim cold total tanpa
mengetahui kondisinya. Lalu ambil minimal 10 sampel hangat untuk READ aman.
Untuk p95 lebih representatif, ambil 20+ sampel dengan jeda, bukan spam request.
WRITE/auth dibatasi fixture, rate limit, dan keamanan; jangan diulang membabi buta.

Di Console, hitung statistik dari angka apiTotalMs yang benar-benar kamu catat:

apiSpeed.stats([720, 810, 940, 1050, 880, 900, 760, 970, 1100, 830]);

Array itu CONTOH perhitungan, bukan hasil tes baru. Ganti dengan hasilmu.
p95 memakai nearest-rank; dengan 10 sampel nilainya sama dengan maksimum.
Jangan menghapus sampel lambat supaya hasil bagus. Catat error/timeout terpisah;
jangan memasukkannya sebagai 0 ms, dan jangan menyembunyikannya dari laporan.

Target ketat "semua percobaan <1 detik":
- tiap sampel sukses total API <1.000 ms; 1.000 ms tepat tidak termasuk <1 detik;
- tidak ada request relevan pending/timeout/gagal;
- respons dan hasil UI benar, bukan fallback/error yang lebih cepat;
- cakupan endpoint dan kondisi uji dinyatakan jelas.

Target p95 <1 detik berbeda: masih mengizinkan sebagian sampel lebih lambat.
Rata-rata <1 detik tidak berarti setiap percobaan <1 detik.
Hasil lokal bukan jaminan SLA produksi atau saat banyak pengguna bersamaan.

Format catatan untuk setiap alur:

Tanggal/jam + zona:
Build/commit + mode DEV/BUILD:
URL host/port + koneksi + device/browser:
Role (tanpa email/password):
Skenario + data uji:
Cache browser ON/OFF + server cache diketahui/tidak:
Jumlah request API + daftar method/path:
Expected status/hasil:
Actual status/hasil:
Sampel API total ms:
Median / p95 / max:
Waktu sampai UI siap (diukur terpisah):
Error/timeout/abort/fallback:
Screenshot/log request_id:
Status PASS / FAIL / BELUM DIUJI / N/A:

Fallback chatbot harus dilaporkan sebagai fallback, bukan "Gemini cepat".
Pesan pertama atau job accepted belum berarti respons final selesai.
Jika suatu saat ada job asynchronous, ukur accepted dan final result terpisah.


7. TELUSURI LAMBATNYA DI LOG SERVER

Browser tidak menampilkan seluruh call internal. Log operasional berada di
.private\logs di root proyek. Jangan membagikan folder privat mentah.

Terminal PowerShell di root, daftar file dulu:

Get-ChildItem -LiteralPath .private\logs

Pilih file log yang sedang dipakai, lalu (ganti placeholder dengan nama aktual):

Get-Content -LiteralPath '.private\logs\NAMA-FILE-AKTUAL' -Tail 100 -Wait

Command placeholder itu jangan dijalankan sebelum mengganti nama file.
Tekan Ctrl+C untuk berhenti mengikuti log. Cocokkan request_id antar event
request.started, upstream.completed, dan request.completed jika tersedia.
Periksa duration_ms, provider, http_status, outcome, dan mode parallel.
Gunakan HTTP status/sumber balasan untuk membedakan Gemini sukses dari fallback.
Durasi call paralel tidak dijumlahkan untuk menentukan waktu total request.
Request log server tidak mencakup seluruh antrean/network/render browser;
gunakan keduanya, bukan menganggap durasinya selalu identik.

Untuk trace lengkap browser, HAR/Copy as fetch/cURL dapat membawa cookie, body
login, isi chat, data pelanggan, dan query kode akses. Bahkan HAR yang disebut
sanitized belum tentu membersihkan semua body sensitif. Simpan hanya lokal,
review/redact dulu, jangan commit/upload HAR mentah. Bagikan tabel timing dan
screenshot yang sudah disamarkan, bukan credential.

9. KESIMPULAN YANG BOLEH DITULIS

Benar: "Alur Seller membuka Arus Dana: 10 sampel, 2 request per sampel,
median ... ms, p95 ... ms, max ... ms, semua data benar, build lokal ... ."
Salah: "Health 50 ms, berarti seluruh API sudah <1 detik."
Salah: "Satu bootstrap cepat, berarti semua mutasi/chatbot sudah diuji."
Salah: "Fallback instan, berarti respons Gemini selesai <1 detik."

Untuk menyatakan seluruh cakupan selesai, isi setiap kotak bagian 4 dengan hasil,
termasuk expected error dan endpoint WRITE. Cantumkan pengecualian, data uji,
